# Vera observation batch signing — v1 (draft)

Status: **draft, not ratified.** Nothing implements this yet. The current
implementation is described in "What v0 does" below and must be replaced.

This document specifies the exact bytes a Vera observation batch signature
covers, so that an observer written in any language and a host written in any
language agree without having to share code.

## Why this exists

The v0 contract is `sign(JSON.stringify(observations))`. Both current ends
implement it identically, so they interoperate. It is still wrong, in four
independent ways, each of which this spec closes.

| # | v0 defect | Consequence |
|---|---|---|
| 1 | Only the observations array is signed | `source_type` is stored but unauthenticated. Provenance — the product — can be relabelled in transit |
| 2 | Nothing enforces uniqueness | The same signed body replays indefinitely, each time inserting another copy |
| 3 | `JSON.stringify` is not canonical | A Rust observer emits different bytes for identical data. Signatures fail across implementations |
| 4 | No domain separation | A signature made for one purpose can be presented for another |

Defect 3 is the one that matters most for the project's direction. Soma's live
implementation is Rust. The moment an observer is written in Rust, v0 breaks —
not visibly, but as signatures that fail to verify for reasons that look like
corruption.

## Signed bytes

```
signed_bytes = DOMAIN || canonical_json(envelope)
```

`DOMAIN` is the UTF-8 encoding of:

```
somavera:vera-observation-batch:v1\n
```

The trailing newline is part of the domain. This follows the convention Soma
already applies across all twelve of its signing contexts; a signature over
these bytes cannot be replayed into any other Soma or Vera context, because no
other context prefixes these bytes.

`||` is byte concatenation. The signature algorithm is Ed25519 over
`signed_bytes` with the submitting identity's Soma key.

## Envelope

```json
{
  "batch_id": "0f1c…",
  "observations": [ … ],
  "schema_version": "somavera.vera-observation-batch.v1",
  "soma_did": "did:soma:…",
  "source_type": "git",
  "submitted_at": "2026-07-28T01:22:03Z"
}
```

Exactly these six fields. No more, no fewer.

| Field | Rule |
|---|---|
| `batch_id` | 32 lowercase hex characters, generated by the observer from a CSPRNG. Not a hash of the content — two honest batches with identical content must be distinguishable |
| `observations` | Non-empty array. Element schema is out of scope here |
| `schema_version` | Exactly the string above |
| `soma_did` | The submitting identity. Included so the binding is signed, not merely asserted |
| `source_type` | The provenance label. Signed, closing defect 1 |
| `submitted_at` | RFC 3339 UTC, `Z` suffix, second precision, no fractional part |

A host **must reject** an envelope carrying any unrecognised field rather than
ignoring it. Ignoring unknown fields lets a future version's meaning be
smuggled past an older host that does not understand it.

## Canonicalization

`canonical_json` is RFC 8785 (JCS), with Soma's strictness: the canonicalizer
**rejects** ambiguous input instead of normalizing it.

Rejected, not repaired:

- lone surrogates
- non-finite numbers
- negative zero
- integers outside the safe-integer range — encode exact quantities as decimal strings

Object keys are sorted by UTF-16 code unit. No insignificant whitespace.

The reference implementation is `js/src/canonicalize.mjs` in `hey-vera/soma`.
It is the normative behaviour where this prose and that code disagree.

### Implementations do not share code

Each implementation carries its own canonicalizer and proves agreement against
shared conformance vectors. Two independent implementations that agree on
vectors is a stronger guarantee than one shared library that cannot be wrong
because it is only run once.

Vectors live in `test-vectors/vera-observation-batch/v1/` in `hey-vera/soma`,
beside the Soma vectors, because agreement between implementations is a
protocol property rather than a Vera-internal one.

## Host obligations

A conforming host, on receiving a batch:

1. Parses the body. Rejects unknown top-level envelope fields.
2. Resolves `soma_did` to a registered public key. Unknown DID → `404`.
3. Recomputes `canonical_json(envelope)` from the parsed envelope. **Verification
   is over the recomputed bytes, never over the received bytes.** A client that
   sends non-canonical JSON is not rejected for that alone; the canonical form
   is the identity of the content.
4. Verifies Ed25519 over `DOMAIN || canonical`. Failure → `403`.
5. Rejects `submitted_at` outside ±300 seconds of host time → `403`. This bounds
   replay independently of step 6, and bounds it even against a host that has
   lost its uniqueness index.
6. Enforces uniqueness of `(soma_did, batch_id)`. A duplicate is **not** an
   error: the host returns `200` with the original batch record. Replay must be
   idempotent rather than fatal, so that an observer retrying after a network
   timeout is not punished for it.
7. Only then stores.

Steps 5 and 6 together close defect 2. Neither alone is sufficient — a
timestamp window without uniqueness allows replay inside the window, and
uniqueness without a window requires the index to be retained forever.

## What v0 does, for comparison

```
sign(JSON.stringify(observations))
```

No domain, no metadata, no canonicalization, no replay binding. Stored
`signedPayloadHash` is computed and never read.

## Migration

v0 and v1 are not compatible and no attempt should be made to make them so. The
`schema_version` field is absent in v0 bodies, so a host can accept both during
transition by routing on its presence, and must log v0 acceptance as a
deprecation. No production data exists yet, so the transition window can be
short.

## Open questions

- Should `observations` elements be individually signed so a host can discard
  one without invalidating the batch? Deferred: it multiplies signature cost by
  batch size, and no consumer needs partial batches yet.
- Should the envelope carry the observer's software version? It aids debugging
  and leaks a fingerprint. Deferred pending the redaction design.
- Post-quantum: the signature suite must become a field rather than a constant
  before this leaves draft, matching Soma's existing suite agility.
